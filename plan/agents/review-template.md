# Review Agent Template

## Review scope

Identify the reviewed slice, implementation plan, diff or PR, and any explicitly requested focus areas.

## Findings

List actionable findings first, ordered from highest to lowest severity.

Each finding should include:

- severity
- concise description of the problem
- file and location, when available
- why it matters to correctness, accessibility, performance, authoring, or scope
- reproduction or supporting evidence where practical

Do not report a subjective visual preference as a defect without connecting it to the approved design brief or a concrete reader problem.

## Missing verification

Identify important missing tests, skipped checks, unsupported browser claims, or gaps between the active stage and the evidence provided.

## Residual risks

Document meaningful remaining uncertainty without inventing work that belongs to a later stage.

## No-findings statement

If there are no actionable findings, say so explicitly and note any review limitations.
